# Отчёт о тестировании FlowBoard

**Дата:** 12 октября 2026 г.
**Объект:** мобильное приложение FlowBoard (Flutter, Android/iOS) и сервер (NestJS), ветка `main`.

**Итог:**
- приложение: 178 автотестов: 177 пройдено, 1 пропущен в обычном прогоне (live-тест; он запускается только при работающем сервере, отдельный прогон пройден);
- сервер: 59 тестов, все пройдены;
- покрытие кода тестами: приложение — 77,5 % строк, сервер — 90,0 % строк;
- ручная проверка на эмуляторе: 38 тест-кейсов, все пройдены;
- найдено и исправлено 25 дефектов, открытых нет.

## 1. Цель и объём

**Цель:** подтвердить, что FlowBoard выполняет требования технического задания и критериев курсовой работы. Требования такие:
- регистрация и авторизация;
- главная страница и навигация;
- профиль;
- работа с данными (создание, чтение, изменение, удаление);
- поиск и фильтры;
- офлайн-режим и синхронизация;
- обновления в реальном времени;
- язык интерфейса и тема.

**Что проверялось:**
- мобильное приложение: логика, экраны, доступность, сценарий пользователя целиком;
- сервер: API, синхронизация, Socket.IO, уведомления, ограничение частоты запросов;
- их совместная работа на эмуляторе Android.

## 6. Найденные дефекты

Все дефекты исправлены. Для ошибок в логике и доступности после исправления добавлен тест, который ловит эту ошибку. Как проверены остальные:
- Д-05, Д-07, Д-08, Д-10, Д-11, Д-13, Д-14 — повторно на эмуляторе;
- Д-21, Д-22 — по изменениям в проекте iOS; сама сборка iOS запускается в CI вручную;
- Д-09 — чтением кода: прочерк виден только доли секунды при запуске.

| № | Дефект | Как найден | Причина | Исправление |
|---|---|---|---|---|
| Д-01 | После обычного выхода на экране входа появлялось «Сессия истекла» | Эмулятор | Поток пользователя доставлял `null` уже после того, как кубит сбросил флаг «идёт выход» | Кубит сам выставляет состояние «вышел»; фейковый репозиторий теперь ведёт себя как настоящий (`b46243b`) |
| Д-02 | Системная «Назад» во время поиска закрывала всю доску | Эмулятор | Поиск не перехватывал «Назад» | `PopScope`: первое нажатие закрывает поиск (`36b313b`) |

Д-01 был в коде с фазы 2. Автотесты его не ловили, потому что фейковый репозиторий отправлял событие синхронно, а настоящий — после записи в защищённое хранилище. Ручная проверка на эмуляторе нашла и этот дефект, и ещё 14 недочётов интерфейса (Д-02…Д-05, Д-07…Д-14, Д-24, Д-25). Поэтому автотесты её не заменяют.

Один раз при замере покрытия сервера тест `PATCH /users/me` упал по тайм-ауту: параллельно шёл замер покрытия приложения, а хеширование паролей (argon2) под инструментированием медленное. Это не дефект кода: повторный прогон без параллельной нагрузки прошёл, обычные прогоны укладываются в 35–60 секунд.

## 7. Непрерывная интеграция

На GitHub Actions два workflow, они запускаются при каждом push:

| Workflow | Проверки |
|---|---|
| API | eslint, prettier, проверка типов, модульные тесты, e2e на контейнерах PostgreSQL и Redis |
| Mobile | форматирование, `flutter analyze`, все тесты, проверка актуальности сгенерированного кода, сборка отладочного APK (доступен как артефакт) |

Сборку iOS (без подписи) запускает отдельный workflow на macOS вручную.

## 8. Как повторить

```powershell
docker compose up -d

# Сервер
cd apps/api
npm run lint; npm run format:check; npm run typecheck; npm test; npm run test:e2e
npx vitest run --config ./vitest.config.e2e.ts --coverage   # покрытие

# Приложение
cd ../mobile
flutter gen-l10n; dart format --set-exit-if-changed lib test tool; flutter analyze; flutter test
flutter test --coverage                                    # покрытие: coverage/lcov.info

# Real-time на двух «устройствах» (сервер должен быть запущен)
$env:FLOWBOARD_LIVE_API = 'http://localhost:3000'; flutter test test/live; Remove-Item Env:FLOWBOARD_LIVE_API
```

## 9. Вывод

Функции из технического задания и критериев курсовой работы проверены автотестами и вручную на эмуляторе Android:
- splash;
- регистрация и вход;
- главная;
- навигация;
- профиль;
- работа с досками и карточками (создание, изменение, удаление);
- поиск и фильтры;
- офлайн-режим и синхронизация;
- обновления в реальном времени;
- три языка и две темы;
- выход.

Проходят 236 автотестов: 177 в приложении и 59 на сервере. Live-тест обновлений в реальном времени запускается отдельно при работающем сервере и тоже пройден. Покрытие строк — 77,5 % в приложении и 90,0 % на сервере. Все 25 найденных дефектов исправлены.

Ограничения проверки:
- push-уведомления проверены без настоящего проекта Firebase: сервер и приложение работают без него, логика отправки покрыта тестами с фейковым отправителем;
- сборка под iOS проверяется только в CI на macOS, на устройстве iOS приложение не запускалось;
- real-time проверен live-тестом (два клиента в одном процессе против настоящего сервера), а не на двух эмуляторах одновременно.
